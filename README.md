# Dony's Lifts for iPhone, iPad, Apple Watch, and Mac

The app's name and Icon Composer icon emphasize gym-set recording. The active `DonyLifts2026.icon` is under `Setlog/Resources`; earlier icon designs are preserved under `DesignArchive/Icons` and are not included in the Xcode navigator. The in-app accent stays bright green. The bundle identifier is unchanged and the workout data format remains backward-readable, so installing this build over the existing app keeps its saved workouts.

Motion is native SwiftUI: a slow ambient glow travels behind the workout header, cards respond to scrolling, and workout buttons spring when pressed. Releasing a button triggers a brief green outline bloom with tiny glints on iPhone/iPad, a compact bloom on Mac, and a smaller ring on Apple Watch. The effect is triggered once per tap rather than running continuously. Reduce Motion disables the ambient, scroll, press, and tap-bloom animations.

The week is displayed Monday through Sunday with prominent weekday buttons rather than numbers. A green-tinted button with a check means the day is finished at 80% or above; an outline means only that the day is selected. Unfinished buttons show their percentage or Today, while finished buttons say Done. The selected day's header says Finished or Not finished plainly. The iPhone/iPad This week card shows finished checkmarks without redundant percentages; unfinished days still show their percentage. Its full-year calendar keeps actual completion percentages. Dated history is saved with the workout record from this version onward; older weeks cannot be reconstructed reliably from the legacy seven-day schedule. Unlock entries to add or remove a workout card. The sunrise/sunset mode now converts solar event times to the device's local day correctly.

Native SwiftUI version of the private Setlog workout tracker. It supports the same seven-day schedule, Friday plan choice, target and last values, set-level editing and completion, notes, the 80% finish rule, and location-based day/night appearance.

The iPhone and iPad use the same universal `Setlog` target and existing bundle ID. iPad has an adaptive bento-style dashboard: seven full-width day tiles, three summary columns in landscape or two in portrait, and a multi-column exercise grid. The `DonyLiftsWatch` watchOS companion is embedded in that app. The separate `DonyLiftsMac` target is native SwiftUI for macOS. Workout data uses the same Firebase account on iPhone/iPad and Mac; the watch sends changes through the paired iPhone. Apple Fitness rings remain on-device and are not uploaded.

On Apple Watch, open the companion after opening Dony's Lifts on the paired iPhone. Browse a weekday, tap an exercise, tap a set to mark it done, or unlock to edit load/reps and add/delete sets. The current Friday plan is shown, but choose between the two Friday plans on phone or Mac. If the watch is temporarily offline, changes queue for delivery to its paired phone. The watch is not a standalone Firebase client.

On Mac, select a weekday in the sidebar and use the same Setlog email/password as the website and phone. The Mac downloads the established shared record, refreshes while open, and pauses upload if it detects a conflicting edit. Its local file and keychain are separate from the iPhone's. There is no automatic local-data migration between platforms; the shared Firebase record is the bridge.

To remove a set, tap **Unlock entries**, then the red minus button beside that set. Confirm the deletion; the remaining sets renumber and save automatically.

## Apple Fitness rings

On the iPhone, tap **Connect** in the Apple Fitness card and allow Dony's Lifts to read Activity summaries in Health. It displays real Apple Fitness rings for the selected date. Tap a weekday or use the date picker to show another date; tap **Refresh** to query Health again. The app also refreshes when returning to the foreground. The separate **Finished** switch and workout progress refer only to your Setlog sets. The workout schedule remains a recurring seven-day template, while new dated completion snapshots populate the calendar. Fitness data stays on the iPhone: it is not added to Firebase, the website, or JSON backups. If no Activity summary is available, check Health → profile picture → Apps → Dony's Lifts and allow Activity read access; also confirm Fitness has rings for that date on that iPhone. HealthKit does not tell the app whether read access was denied, so an empty result can mean missing permission or missing data.

## Shared record setup

1. In Firebase Console, enable Email/Password authentication and create Firestore in Production mode. Publish the owner-scoped rules in the accompanying `firestore.rules` file.
2. Open the [private Setlog site](https://dony-setlog.setyautama1999.chatgpt.site), confirm the five Thursday Hanging Leg Raise sets, and create or sign in to your Setlog email/password account. The website establishes the first shared copy. Wait for **Shared with your iPhone** and **Saved privately**.
3. Install this updated iPhone build, scroll to **Shared data**, and sign in with the same email/password. The shared website record is downloaded; your earlier local iPhone record is backed up first.

The website, iPhone/iPad, and Mac save locally while a cloud write is pending and check for shared changes while open. A concurrent edit pauses native shared saving and asks which copy to keep rather than silently overwriting one. The website's previous private database and the supplied JSON backups are not deleted. The iPhone/iPad still has **Import JSON** and **Back up** for manual recovery. Do not sign in on a new device before the website has established the shared copy.

## Build and install

Open `Setlog.xcodeproj` in Xcode 27 or later. The deployment targets are iOS/iPadOS 17, watchOS 10, and macOS 14. Choose your team in **Signing & Capabilities** for **Setlog**, **DonyLiftsWatch**, and **DonyLiftsMac**, and leave **Automatically manage signing** enabled. The iPhone/iPad target has a HealthKit read entitlement but no iCloud entitlement. Select an iPhone or iPad and run **Setlog**. To install on a paired Apple Watch, enable automatic app installation in the Watch app or select a paired Watch run destination. To run on Mac, select the **DonyLiftsMac** scheme and **My Mac**. Physical-device installation still depends on your Apple signing/provisioning setup.

The iPhone/iPad bundle ID remains `com.setyautama.setlog` so updates keep local data. Do not change it merely to silence a signing error: that would install a separate app without the existing local record. The watch and Mac bundle IDs are `com.setyautama.setlog.watchkitapp` and `com.setyautama.setlog.mac`. For TestFlight you need an Apple Developer Program team, not a free Personal Team. With a paid team, use **Product → Archive → Distribute App → TestFlight Internal Only**. This weekday-button update built and installed on Dony's iPhone 11, iPhone 15 Pro, and Apple Watch Series 10. The native Mac build was installed at `~/Applications/DonyLiftsMac.app` and opened with the shared record. The iPad Air still has an earlier build: this update was rejected because the iPad has no free storage. Free some iPad storage before rerunning the Setlog scheme or installing this build. Nothing was deleted from the iPad. This version has not been uploaded to App Store Connect.

The starter schedule is bundled with timestamp zero. Existing imported or saved sets are never regenerated from the template. Shared workout data uses Firebase, not iCloud, and the supplied Firebase iOS configuration is bundled as `GoogleService-Info.plist`. The active HealthKit entitlement is `Setlog/Configuration/Setlog-HealthKit.entitlements`; an older unused entitlement is preserved under `DesignArchive/Configuration` and is not attached to the target. Do not enable iCloud capability for this version.
